## 1. Gán quản lý theo khu vực — guard gỡ, đồng bộ `zone_managers`, thông báo tự gán

Nguồn: `BE-NEED-zone-manager-notify-va-guard-2026-08-20.md`

### 1.1 Chặn `DELETE /zones/{zoneId}/manager` khi còn hợp đồng sống

**File:** `ZoneAssignmentServiceImpl`

- `removeManager()` (DELETE) gọi `assertNoLiveContracts(zoneId)` rồi mới `doRemoveManager(zoneId)`.
- Đếm hợp đồng `DRAFT` / `PENDING` / `ACTIVE` — **không** đếm `PropertyStatus.RENTED` (nhà chia phòng có khách vẫn `ACTIVE`).
- `EXPIRED` không chặn.
- Message tiếng Việt, chỉ liệt kê loại nào thực sự có.
- `transferManager()` gọi `doRemoveManager()` (không guard) để luồng bàn giao không bị gãy.
- 404 khi không có bản ghi `zone_managers`: `Không tìm thấy phân công quản lý cho khu vực này`.

### 1.2 Đồng bộ `zone_managers` khi gán nhà lẻ

**File:** `PropertyOnboardingServiceImpl`

- `assignOperationManager()` và `changeOperationManager()` upsert `zone_managers`.
- Khu vực dựng bằng gán từng nhà có bản ghi phân công → `hostConfirm` tự gán được.

**Backfill (chạy tay trên DB):** `src/main/resources/db/backfill-zone-managers.sql`

Khu vực đang lẫn nhiều quản lý bị bỏ qua — host tự chốt.

### 1.3 Thông báo khi host duyệt và hệ thống tự gán

`hostConfirm()` khi khu vực đã có `zone_managers`:

- Set `operationManagerId` + `managedBy` + `managerAcceptedAt`.
- In-app + push `PROPERTY_ASSIGNED` (`PropertyDetail`, `params.propertyId`).

**FE:** gỡ bị chặn → HTTP 422, hiện `message` nguyên văn. Tự gán lúc duyệt → `type = PROPERTY_ASSIGNED`. Sau deploy **chạy SQL backfill**.

## 2. Lưu người đón khách trên hợp đồng

Nguồn: `BE-NEED-luu-nguoi-onboard-hop-dong-2026-08-20.md`

`assignedManager` vẫn là người phụ trách hiện tại (được ghi đè khi đổi QL khu vực). Thêm cột lịch sử, ghi một lần lúc onboard.

### Cột mới

| Cột | Ý nghĩa |
|---|---|
| `onboarded_by_manager_id` | Người thực sự đón khách / confirm HĐ |
| `onboarded_at` | Thời điểm ghi nhận |

- Set trong `confirmContract()`, chỉ khi còn trống (idempotent không ghi đè).
- **Không** set ở `acknowledgeHandover` — API đó do **tenant** gọi, current user không phải quản lý.
- `updateAssignedManagerByZoneId`, `removeAssignedManagerByZoneId`, `reassignManagerForProperty` **không đụng** hai cột mới.

DDL tay (nếu không dựa `ddl-auto`): `src/main/resources/db/add-onboarded-by-manager.sql`

Không backfill HĐ cũ — để trống, FE hiện `—`.

### DTO (admin / host / manager / tenant)

Cả ba:

- `TenantContractResponse` — admin, manager, tenant (chi tiết `GET /tenant-contracts/{id}`), host nếu dùng endpoint chung
- `TenantContractDetailResponse` — thêm field sẵn
- `HostContractDto` — list host

Field:

```
assignedManagerId, assignedManagerName
onboardedByManagerId, onboardedByManagerName, onboardedByManagerPhone, onboardedAt
```

`assignedManager*` thêm vào `HostContractDto` và `TenantContractDetailResponse` (trước đó thiếu). Tenant/host chi tiết dùng `TenantContractResponse` đã có `assignedManager*` từ trước.

**FE:** hai dòng riêng — “Quản lý phụ trách hiện tại” vs “Người đón khách” (tên · ngày · SĐT). HĐ cũ: người đón khách `null`.

## 3. Import HĐ nháp — cho import từng phần

Nguồn: `BE-NEED-import-tenant-draft-partial-2026-08-20.md`

`POST /api/v1/import/tenant-draft-contracts-excel`

- Query `skipInvalidRows` (mặc định `false`) — không đổi hành vi cũ: một dòng lỗi → chặn cả file.
- `skipInvalidRows=true`: import / dry-run **chỉ dòng sạch**. Dòng lỗi **không** được tạo HĐ (luật giữ nguyên).
- Response 200: `contractsProcessed` = dòng sạch, `contractsSkipped` = số dòng bỏ (unique `rowNumber`), `errors` = danh sách lỗi kèm `code`.
- Mọi dòng đều lỗi → vẫn 400 `Không có dòng nào hợp lệ để import`.

`BulkImportErrorResponse.code` (import HĐ nháp):

| `code` | Loại |
|---|---|
| `PROPERTY_NOT_ACTIVE` | Tạm thời — chờ host duyệt giá |
| `PROPERTY_NO_INBOUND_LEASE` | Tạm thời |
| `OCCUPANCY_OUT_OF_LEASE` | Sai dữ liệu |
| `MISSING_FIELD`, `INVALID_DATE`, `INVALID_NUMBER`, `INVALID_FIELD` | Sai dữ liệu |
| `PROPERTY_NOT_FOUND`, `PROPERTY_AMBIGUOUS`, `ROOM_NOT_FOUND`, `ROOM_OCCUPIED`, `DUPLICATE_IN_FILE` | Sai dữ liệu |

**FE:** gọi `skipInvalidRows=true`, phân loại theo `code` (không dò chuỗi `"chưa ACTIVE"`). Bỏ bước cắt file client-side.

## 4. Nhà chia phòng — host duyệt xong phòng kẹt `DRAFT`

Nguồn: `BE-BUG-phong-ket-DRAFT-sau-khi-host-duyet-2026-08-20.md`

`hostConfirm` tự gán QL theo khu vực → nhà `ACTIVE` luôn, **không** đi `assignOperationManager` / `activatePerRoom`. Trước đây phòng chỉ được `DRAFT → AVAILABLE` ở bước gán tay.

- `confirmPerRoom()`: nếu nhà đã `ACTIVE` thì set phòng `AVAILABLE` sau khi gán giá. Nhà `PENDING_OPERATION_MANAGER` giữ `DRAFT` như cũ.
- `confirmWholeHouse()`: cùng logic — phòng DRAFT của nhà nguyên căn `ACTIVE` cũng lên `AVAILABLE`.

**Backfill tay:** `src/main/resources/db/backfill-draft-rooms-on-active-property.sql`  
(cột xóa mềm là `is_deleted`, không phải `deleted`). Chạy trên DB thật cho MTX#110 và nhà tương tự.
